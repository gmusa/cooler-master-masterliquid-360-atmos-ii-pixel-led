# Pixel dashboard — local preview milestone

Python 3.11+ and [uv](https://docs.astral.sh/uv/): run `uv sync` in this checkout, then `uv run pixel-dashboard preview --config examples/config.toml --frames 20 --output preview.gif`. Alternatively, when Pillow is already installed: `PYTHONPATH=src python -m pixel_dashboard preview --config examples/config.toml --frames 20 --output preview.gif`. Preview is bounded to 1–300 frames, uses synthetic sample readings, and never opens USB or probes sensors. Output path is caller-selected. `--locked` previews the locked playlist; it does not query or configure Noctalia.

TOML requires `[normal]` and `[locked]`, each with a nonempty ordered `[[...widgets]]` list. Names: `clock`, `date`, `cpu`, `gpu`, `animation`. Options `duration` (seconds, >0 to 3600), `brightness` (0–100), `rotation` (0, 90, 180 or 270 degrees), `fps` (0.01 to 100, GIF timing resolution 10 ms), `mask` (boolean) inherit from `[defaults]` to environment to widget; unknown fields are errors. `ConfigStore.poll()` checks file mtime and size synchronously; changed files are validated and swapped only on success, retaining the last good configuration on errors. `.error` holds the latest diagnostic. The bounded preview polls once per frame without threads. A future live host must drive polling and select normal/locked; USB rendering, service installation, and Noctalia hooks are deferred. Preview uses a logical clock starting at zero: each frame selects the widget owning its elapsed time in the ordered, repeating playlist, then advances by that widget's `1/fps` seconds. `--trace` prints frame time and widget. Brightness, rotation and the exact 32×32 LED topology mask are applied to the image; GIF timing is quantized to 10 ms. The non-LED preview corner (0,0) carries a transparent per-frame marker so visually identical frames remain distinct in the GIF. Mask row bounds derive from cm-pixel 0.1.0 `cmpixel/layout.json` (copyright 2026 Feiko, MIT); its license is included at `src/pixel_dashboard/LICENSE-cmpixel.txt`.

Sensor readers are read-only subprocess adapters: `sensors -j` k10temp Tctl and `nvidia-smi` RTX 5070 temperature/utilization. CPU/GPU frames show labels, numeric temperature and available utilization with a bar; missing measurements show `--`, not fabricated readings. Preview's synthetic CPU sample has temperature only (no CPU usage), while its synthetic GPU sample has temperature and utilization. Partial/unavailable live readings remain unset. NVIDIA's `fan.speed` is a percentage, not RPM, so fan RPM remains unavailable. CPU usage is unavailable until `/proc/stat` access is approved. The optional `open_hidraw_backend()` imports `hidraw` explicitly rather than relying on `hid` selection; no USB/device integration is enabled in this milestone.

Test: `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 PYTHONPATH=src python -m pytest -q tests`.
